# Changelog

All notable changes to ptywright will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

Third release. Focuses on making `ptywright repl` a real Lua 5.4 operator console, improving REPL startup and rendering ergonomics, and tightening the built-in `claude-code` plugin against newer Claude Code TUI screens without adding Claude-specific Rust surface area.

### Changed

- **`ptywright repl` now evaluates real Lua 5.4 instead of a hand-rolled DSL.** The bespoke lexer/parser/dispatcher in `src/repl/command.rs` is replaced by an embedded `mlua` VM with the full Lua standard library. Every line typed at `pty>` is loaded as a Lua chunk; REPL-exposed globals (`session`, `send`, `wait`, `matches`, `screen_stable`, `turn`, `cancel_wait`, `re`, `ms`, `s`, `plugins`, `state`, `transcript`, `screen`, `view`, `inspect`) translate into the existing `adapter.*` JSON-RPC surface. The wire shapes are unchanged — the operator-facing change is syntactic. Notable consequences:
  - **Real expressions and control flow.** `for i = 1, 3 do session.spawn("claude-code") end`, `local s = screen.snapshot(); s.cursor`, `os.date()` — anything Lua 5.4 supports.
  - **Trailing-table kwargs.** `session.spawn("claude-code", { rows = 24 })` is the new shape (positional + opts table); the Lua-sugar form `session.spawn{ "claude-code", rows = 24 }` works too. The old `session.spawn("claude-code", rows=24)` Python-style kwargs are gone — Lua doesn't have them.
  - **Regex / duration literals replaced by helpers.** `r"…"` → bare string or `re("…")` for documentation; `250ms` → bare integer or `ms(250)`; `s(2)` returns `2000`. Inside `wait` / `matches` / `screen_stable` the bare forms are accepted directly so most call sites stay short.
  - **Bundled `inspect.lua` (kikito, MIT)** is the default pretty-printer for return values. String results render unquoted; tables render via inspect; `ScreenSnapshot`-tagged tables render through the styled inline view (same renderer as the legacy `view()` DSL).
  - **Multi-line input via reedline's `Validator`.** Unclosed blocks (`for ... do`, `function ... end`, `{ a = 1,`) open a `…` continuation prompt; the validator keys on `mlua::Error::SyntaxError { incomplete_input: true }`.
  - **`matches` / `screen_stable` are matcher constructors.** They return tagged tables `{ __pty_matcher = "regex" | "stable", … }` that `wait(...)` / `turn(..., wait = …)` unwrap into the right `adapter.wait` params. Standalone calls emit no RPC traffic.
- **REPL completer is Lua-introspection-driven.** Top-level identifier completion (`sess<TAB>` → `session`) iterates the live Lua globals filtered through an explicit REPL-globals whitelist (so stdlib tables like `string` / `math` / `io` / `os` don't drown the picker). Member access (`session.<TAB>` → `spawn / resume / list / live / attach / close`) iterates `pairs()` on the resolved table. String-arg completion paths (`session.spawn("<TAB>`, `send.key("<TAB>`, `:attach <TAB>`) still come from `PluginCache` / `AdapterCache` / `KEY_NAMES` — adding a new binding now lights up in the completer with zero extra wiring.
- **REPL highlighter sources its identifier list from the same whitelist** plus Lua 5.4's reserved-word set (`local`, `function`, `end`, `for`, `while`, `if`, `then`, `else`, `do`, `return`, `nil`, `true`, `false`, `and`, `or`, `not`, …). Single- and double-quoted strings, line comments, long-bracket strings, and negative numeric literals are all recognised.

### Fixed

- **`claude-code` classifier precision around prose that resembles UI chrome.** Rate-limit phrasing now uses guarded banner checks instead of bare line prefixes, suppressed-permission detection requires a standalone TUI row, and local UI / settings-style usage screens no longer pre-empt the mid-turn `prompt_submitted` fallback on ordinary assistant replies.
- **`claude-code` `send_prompt` now avoids Claude's bracketed-paste collapse path.** The plugin-owned action plan streams ordinary input bytes before submitting, so any consumer using `adapter.send { intent = "send_prompt" }` gets reliable prompt submission, including `scripts/claude-stream.py` and external wrappers. The classifier treats a submitted prompt still visible in the editable input row as "not submitted yet" instead of accepting input echo as a real turn start, and it avoids dumping raw PTY transcript bytes after a normally streamed completion.
- **`claude-code` structured turn output preserves path-like prose.** Assistant lines such as `/tmp/output` and `~/project` are no longer mistaken for Claude Code header chrome, and post-marker status-bar detection no longer treats ordinary email-address prose as a footer row.
- **`ptywright serve --socket <path>` now creates the runtime parent directory before binding.** Previously, on a fresh install where `~/.ptywright/` (or the directory `PTYWRIGHT_HOME` points at) didn't exist yet, `UnixListener::bind` returned `ENOENT` and the server crashed before printing anything useful. The REPL's auto-spawn flow with stderr piped to `/dev/null` made this look like a 5-second hang followed by a generic "socket did not start accepting connections" timeout. The server now runs `create_dir_all(parent)` before any bind so the first-run auto-spawn path works on clean systems.
- **`session.resume{ prior = "id" }` (the documented legacy alias for `prior_adapter`) is honoured again.** The Lua port wrote `opts.get::<Option<String>>("prior_adapter").or_else(|_| opts.get::<Option<String>>("prior"))`, but `mlua::Table::get::<Option<_>>` returns `Ok(None)` when the key is absent — so `or_else` only fired on type errors and the alias path was unreachable. The resolver now falls through to `prior` *on absence* while still propagating a real type error from the canonical key (so `prior_adapter = {}` errors instead of silently being replaced by whatever `prior` resolves to).
- **`ptywright repl --framing lsp` no longer hangs when it has to auto-spawn the server.** The auto-spawn path previously always invoked `serve --socket <path>` with the server's default NDJSON framing, so a `--framing lsp` REPL ended up shouting LSP frames at an NDJSON server and timing out on the first call. The selected framing is now plumbed through to the child as `--framing <ndjson|lsp>`.
- **Lua brace-call sugar with no kwargs works.** `session.spawn{"claude-code"}`, `session.attach{"all"}`, `send.intent{"approve"}` — every documented call site with only positional args inside braces — used to fall through to the generic positional path and leave the table itself as `positional[0]`, which then errored with `expected a string`. `read_call` now treats any lone-table arg as the combined form (array part → positional, string keys → opts), so the empty-kwargs brace form unpacks the way the docs and completer have always promised.

### Added

- **`claude-code` TUI classifier coverage for newer local dialogs/screens.** The built-in plugin now recognises enter-plan-mode, `Ready to code?` plan approval, richer permission option lists, model picker effort controls, settings-style `/usage`, current rate-limit banners, external-editor waits, suppressed permission waits, and representative local slash-command screens without adding Claude-specific Rust APIs. New plugin-owned intents `choose_option`, `model_effort_left`, and `model_effort_right` drive those selectors through generic text/key actions.
- **`claude-code` streaming metadata for in-flight turns.** While a submitted prompt is still running, the classifier can expose best-effort `metadata.turn.partial_text` and structured visible tool metadata, including Claude Code's Explore-agent progress as generic `Agent` tool records.
- **`ptywright repl` auto-spawns the server when none is running.** Running `ptywright repl` with no transport flag now starts a background `ptywright serve --socket <default>` (current binary, fully detached stdio) when nothing is listening at `~/.ptywright/socket`, waits for the socket to accept connections, and connects. On REPL exit the operator is prompted whether to shut the auto-started server down (default) or detach it so other clients can keep using it. Non-interactive stdin defaults to shutdown so scripted invocations never leak a daemon process. Explicit `--socket <path>` skips the auto-spawn — that flag implies the operator is managing the server themselves.
- **REPL completer recognises every Lua call shape for first-string arguments.** Previously only the parenthesised + quoted form was wired (`session.spawn("<TAB>`), so the brace-form `session.spawn{"<TAB>` and the string-sugar form `plugins.describe "<TAB>` silently fell through to top-level identifier completion. The completer now detects paren, brace, and string-sugar opener shapes uniformly (with or without internal whitespace) and surfaces the matching cache for `session.spawn` / `session.resume` / `plugins.describe` (plugin names), `send.key` (key names), `session.attach` (server-side adapter ids + `all`), and `session.close` (local adapter ids). When the operator presses TAB before typing the opening quote (e.g. `session.spawn(<TAB>`), the suggestion value includes the surrounding quotes so it lands as `"<name>"` — no awkward retype-the-quote step. Kwarg-led first args (`session.spawn{ rows = 24, …`) are explicitly skipped so identifier completion takes over.
- **Rotating startup tip + `:tips` meta command.** Each REPL launch surfaces one rotating one-liner under the banner (clock-keyed, so subsequent runs cycle through the set) plus a line pointing at `:tips for a tour · :help for the command reference`. The new `:tips` meta command renders a curated five-section guide (list/spawn, drive, atomic send+wait, inspect, tabs/focus) with the same section-aware layout as `:help`. The two surfaces are deliberately split: the banner tip is for ambient discovery, `:tips` for an intentional refresher.
- **`view()` / `screen.snapshot()` renderer trims leading blank rows symmetrically.** `print_screen` used to drop only trailing blank rows, so the Claude Code welcome screen (content in rows ~6–18 of a 60-row PTY) painted with five rows of dead whitespace between the divider and the first content line. The trim is now symmetric with the cursor row honoured as a floor on both ends, and the footer reports both directions (`5 above / 42 below blank row(s) hidden`).
- **`view()` width adapts to content + terminal size.** Each row is trimmed to its rightmost non-blank cell so a 30-col line doesn't trail 170 cols of empty padding, and the whole rendered slice is clamped to `min(content, term_cols - leading_indent, pty_cols)` so a 200×60 PTY doesn't wrap off the side of a narrower host terminal. Truncated rows get a dim `…` marker. The header rule width is sourced from the same effective width so the box top matches the content underneath instead of always running 40–120 cols.
- **Friendlier hint when a REPL command surfaces a bare function value.** Typing `view` (without `()`) used to fall through to inspect.lua and render `<function 1>` — useless to the operator. The render path now intercepts `Value::Function` and emits `<function> · did you mean to call it with ()?` instead, without auto-invoking (which would surprise anyone who actually meant to return a function reference).
- **Tab completion auto-appends `()` to truly nullary REPL globals.** The seven globals that take no arguments (`view`, `state`, `inspect`, `plugins`, `session.list`, `session.live`, `screen.snapshot`) now complete with the parens already in place, so `vi<TAB>` lands as `view()` rather than a bare `view` function reference. The set is deliberately narrow: callables that take arguments (`session.spawn`, `send.text`, `wait`, …) stay bare so the operator can pick between paren and `{...}` sugar; `transcript.snapshot` stays bare too because it accepts an optional `{ redact = bool }` table and forcing `()` would make kwargs awkward.
- **Multi-line input** in `ptywright repl` via reedline's `Validator` trait. Continuation prompt is `…` (configured on the existing `PtywrightPrompt`); submit lands on the closing `end` / `}`.
- **`re("…")` / `ms(n)` / `s(n)` helpers** as REPL-exposed globals. `re` and `ms` are identity (purely documentation-as-code); `s(n)` returns `n * 1000` for seconds → milliseconds.

### Removed

- **Hand-rolled DSL lexer/parser/dispatcher** (`src/repl/command.rs`, ~1700 lines including tests). Meta-command parsing (the `:`-prefixed surface — `:tabs`, `:focus`, `:live`, `:attach`, `:notifications`, `:rpc`, `:help`, `:quit`) lives in the new `src/repl/meta.rs`.

## [0.2.0] - 2026-05-19

Second release. Spans Milestones 23 (claudette adoption readiness), 24 (post-release hardening), 25 (M23.7 cancellation architecture + polish), and 26 (`claude-stream` survival fixes for Claude Code 2.1.143). Two source-breaking Rust API changes (`DefaultTarget` and `ExtensionStateSnapshot` both became `#[non_exhaustive]`) so this is a 0.x minor bump rather than a patch; JSON-RPC wire shapes remain back-compatible.

Highlights: atomic `adapter.turn`; cooperative `adapter.cancel_wait` (`-32005 Cancelled`); plugin-defined `Matcher::Lua` predicates via `PluginRegistry`; in-process event subscription on `Session` / `ExtensionHandle`; streaming `session.output` notifications with structured `MatchOutcome` on `adapter.wait`; PID + SIGTERM→SIGKILL signal ladder; bounded transcript turn segmentation; structured `metadata.*` channels on the `claude-code` plugin (permission, plan, error, usage, status, dialog correlation, login, transcript); classifier hardening for TUI-version-agnostic operation; `ptywright logs --tail` subcommand; `scripts/claude-stream.py` demo driver.

### Added

- **`scripts/claude-stream.py` stuck-detector + rate-limit / quota exit codes + callout-wrapped error detection + submission anchoring.** Several layered fixes that, together, let `claude-stream` survive Claude Code 2.1.143 in production: (1) `--stuck-after-seconds <N>` (default 60): while the classifier reports `thinking`, bails with `exit 5` if no meaningful PTY output (≥ `PASTE_REACTION_BYTES` = 256 bytes) has arrived for `N` seconds. The noise floor is critical — Claude's status bar trickles a few bytes every few seconds even during a true hang (token counter, dim elapsed timer); a naive byte-level reset never fires. The detector accumulates sub-threshold growth and only resets when a 256-byte burst crosses the floor. The 60 s default leaves headroom for Claude to surface its own rate-limit / quota error banner (observed up to ~90 s on the 1M-context tier) so wrappers get exit 3 / 4 instead of exit 5 when an account is throttled. (2) When the classifier surfaces `state="error"` with `metadata.error.kind`, the script discriminates: `rate_limit` → `exit 3`, `quota` → `exit 4`, everything else → `exit 1` — wrappers (claudette, multi-account drivers) can swap accounts on a known code. (3) Submission verification is anchored on the actual prompt text appearing in `body_text` (not the `status_text` input box), not just transcript byte-growth — a paste-echo into the input box was previously enough to false-positive "prompt submitted" even when the trailing Enter was absorbed by the launch banner. If the first attempt fails the anchor check inside 10 s, the script auto-retries once via the plugin's `dismiss_welcome` intent + a second `send_prompt`. (4) Completion-marker latch: when the streaming diff observes a `✻ <Verb> for <N>s` line, the script knows the turn finished even if the classifier never fires `completed_turn` (post-turn `⎿ Tip: …` callouts and spinner repaints can keep it pinned to `thinking`); a subsequent stuck-out is rescued back to `exit 0`. Best-effort `cancel` intent fires before exit so the half-started turn doesn't keep burning server-side resources.
- **`claude-code` plugin: callout-wrapped error detection + new rate-limit / quota anchors.** Closes the gap where mid-turn errors rendered under the `⎿` callout glyph (the same shape Claude Code uses for tool-call results) slipped past `has_error_indicator` / `parse_error_subtype` because the message starts at line position 3+ behind a `⎿ ` (callout + NBSP) prefix, not at column 0. A new `strip_callout_prefix` helper peels both the callout glyph and the NBSP padding before prefix-matching; the existing prefix anchors are now tested against both raw and stripped variants. Adds two new anchored banner prefixes: `you've hit your limit` (CLI `claude --print`-style banner) → `rate_limit`, and `api error: extra usage is required` (mid-turn 1M-context quota error) → `quota`. New fixture `error_quota_extra_usage` covers the callout-wrapped quota case. Together with the streaming-script changes above, this is what enables `claude-stream` to deliver `exit 3` / `exit 4` reliably when one account in a multi-account rotation is throttled.
- **`Matcher::Lua` plugin-defined predicates + `PluginRegistry` trait.** Closes SPEC.md M23.7 architectural item. Adds a fully domain-neutral plugin-driven predicate path: `Matcher::Lua { plugin, predicate, params }` defers to a bound registry at wait time; `PluginRegistry` is an object-safe trait (one method, `evaluate_predicate`) any future WASM/external-process registry can implement. Concrete `LuaPluginRegistry` shipped here. `PredicateContext` exposes the same screen/transcript/markers/cursor view the classifier sees. `PredicateOutcome` accepts boolean shorthand or `{ matched, evidence?, capture? }`. Predicates surface on `adapter.wait` responses as `MatchOutcome::Lua` branches. `Session::set_plugin_registry` / `with_plugin_registry` builders; RPC `adapter.start` binds the server-shared registry automatically. v1 limitation documented: registry-side plugin state is separate from any adapter's classifier-side state.
- **`adapter.cancel_wait` for cooperative cancellation.** Closes SPEC.md M23.7 cancellation item. `adapter.wait` and `adapter.turn` (wait leg) accept an optional client-minted `wait_id`; a separate `adapter.cancel_wait { wait_id }` from another connection interrupts the wait promptly. Idempotent — unknown id returns `cancelled: false`. Cancelled waits surface as `-32005 Cancelled` (distinct from `-32001 Timeout`). REPL DSL gains `cancel_wait("…")` and a `wait_id="…"` kwarg on `wait(...)`. New `ExtensionHandle::wait_with_cancel` / `turn_with_cancel` Rust API.
- **Plugin-driven transcript auto-marking.** Closes SPEC.md M23.10. New domain-neutral primitive `Action::MarkTranscript { label }` (plan-driven mark via `Session::send`) plus `ExtensionStateSnapshot.host_marks: Vec<HostMark>` (classifier-driven mark request channel — the host applies after `classify` returns). `ClassifyContext` gains `markers: &BTreeMap<String, u64>` and `cursor: u64` so plugins can compose metadata like `metadata.transcript = { turn_start, turn_end }` in the same response that requests the mark. Lua host helper `ptywright.action.mark_transcript(label)` gated on `InputWrite`. New `Transcript::markers()` and `Session::transcript_markers()` accessors. The built-in `claude-code` plugin uses this: `send_prompt` stamps `turn_start`; classifier emits `turn_end` `host_marks` on `completed_turn` and surfaces `metadata.transcript`.
- **`ptywright logs` subcommand.** Closes SPEC.md M22.6 optional polish. Tails the newest `<PTYWRIGHT_HOME>/logs/ptywright.*` file with `--lines` (default 20, mirroring `tail -n 20 -f`) and `--filter <SUBSTRING>`. Honours `PTYWRIGHT_HOME`. Poll-based; no new dependencies.
- **Claude-code fixtures co-located under `plugins/claude-code/fixtures/`.** Closes SPEC.md M21.2 deferred item. Plugin authors now have a uniform layout: `plugins/<name>/{manifest.toml, main.lua, fixtures/}`. The auto-enrolling classifier matrix in `tests/lua_classifier_tests.rs` reads from the new path; AGENTS.md, copilot-instructions, applyTo globs, and the docs are all repointed.
- **`plugins/claude-code/manifest.toml`: TOML manifest co-located with `main.lua`.** All claude-code-specific configuration (default program, geometry preset, env preset, declared permissions) lives in this file rather than hand-rolled in `src/plugin.rs`. The Rust core embeds the TOML via `include_str!` and parses it at runtime; the only Rust knowledge of claude-code is "embed this file, parse this file, stamp version from `CARGO_PKG_VERSION`" — no per-field constants. Third-party plugins follow the same `manifest.toml + main.lua` shape.
- **`DefaultTarget.env: BTreeMap<String, String>`** for plugins to declare TUI-knob env vars the host should set when spawning. Matches `Target::env`'s type for direct merge. `adapter.start` resolution: manifest's `default_target.env` is applied first, then caller-supplied `env` overlays it (caller wins on conflict).
- **`claude-code` manifest TUI-simplification env preset** that disables Claude Code 2.1.x features destabilising the classifier (notably `CLAUDE_CODE_SKIP_PROMPT_HISTORY=1`, `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1`, `CLAUDE_CODE_DISABLE_MOUSE=1`, `CLAUDE_CODE_DISABLE_VIRTUAL_SCROLL=1`, `CLAUDE_CODE_SYNTAX_HIGHLIGHT=0`, `CLAUDE_CODE_ACCESSIBILITY=1`, `CLAUDE_CODE_NO_FLICKER=0`, `NO_COLOR=1`). Every var applied automatically by `adapter.start { plugin: "claude-code" }` unless the caller explicitly overrides it.
- **`.envrc`: bootstrap `nix-direnv` 3.0.4** so the devshell is GC-root cached and only re-evaluates when `flake.nix` / `flake.lock` actually change. Stock direnv re-evaluates on every shell entry; with the bootstrap the cached profile is reused.

Spells out concretely what stays out of `src/` (claude-specific identifiers, RPC namespaces, matcher kinds) and what's fine (domain-neutral primitives like `Matcher::Lua`'s string-typed plugin/predicate fields).

Extended `:notifications` meta to accept `adapters=…` / `sessions=…` filter kwargs.
- **Milestone 23 — claudette adoption readiness.** Twelve library-side gaps surfaced by a side-by-side comparison with `claudette/src/agent/*` (2026-05-17). Items 23.1, 23.2, 23.4, 23.5, 23.6, 23.8, 23.9, 23.10, 23.11, 23.12 ship in full; 23.3 ships plan-body + login-URL metadata with structured tool / question metadata and `metadata.flags.exited_plan` flagged as deferred. **23.7 now ships in full** (`Matcher::Lua` predicates + RPC `adapter.cancel_wait`); see the new entries higher in `[Unreleased]` for the architectural details. New surfaces:
  - `Session::pid()`, `Session::signal(Signal)`, `Session::terminate(grace)` SIGTERM→SIGKILL ladder; new `Action::Signal(Signal)` variant and `Signal { Term, Hup, Quit, Int, Kill, User1, User2 }` enum. Unix maps every variant to its libc constant; Windows accepts `Term`/`Kill`/`Int` and rejects the rest with `Error::UnsupportedOnPlatform`. Lua helper `ptywright.action.signal("term")` gated on `SessionKill`.
  - `Target::clear_env()` builder + `Target::env_snapshot()` accessor; new `default_target.required_env` table in plugin manifests for plugin-mandated keys callers cannot override (precedence: parent env → manifest `env` → caller `env` → manifest `required_env`). The `claude-code` manifest moves `CLAUDE_CODE_DISABLE_TERMINAL_TITLE` and `CLAUDE_CODE_DISABLE_VIRTUAL_SCROLL` into `required_env`.
  - `Transcript::mark(label) -> u64`, `Transcript::marker(label)`, `Transcript::slice_between(a, b) -> Option<String>` for turn segmentation (capped at 64 distinct labels). `Session::mark_transcript`, `Session::transcript_marker`, `Session::transcript_slice` forwarders.
  - `claude-code` plugin: `metadata.error = { kind: "rate_limit" | "quota" | "connection" | "auth" | "api" | "unknown", message, retry_after_s? }` on `error` state with anchored banner-prefix detection. New fixtures `error_rate_limit`, `error_network`, `error_auth`, `error_quota`.
  - `claude-code` plugin: `metadata.plan` (scraped from "Plan ready:" / "Approve plan to proceed?" body) on `waiting_for_plan_approval`; `metadata.login.url` extracted from anchored `https://claude.ai/` / `https://anthropic.com/` lines on `waiting_for_login`.
  - `claude-code` plugin: `metadata.dialog_id` minted via FNV-1a from the dialog body fingerprint on `waiting_for_permission`, `waiting_for_plan_approval`, and `waiting_for_trust`. `approve` / `deny` / `approve_trust` / `deny_trust` intents accept optional `dialog_id` param; mismatched id raises a `stale_dialog` Lua error rather than blindly pressing Enter. Locked fixture hashes: `permission=115803ed`, `permission_bash=dcc4608b`, `plan_approval=ffd2a9c4`.
  - `claude-code` plugin: `attach_file { path }` intent (bracketed-pastes the path; validates non-empty + no embedded newlines).
  - `claude-code` plugin: explicit `M.describe()` catalog listing every intent, wait matcher, and classifier state.
  - JSON-RPC: `plugin.describe { plugin } -> { plugin, manifest, intents, wait_matchers, states }`. Falls back to introspecting Lua exports table when the plugin omits `describe()`.
  - JSON-RPC: `adapter.turn { adapter, send: { intent, params }, wait: { intent?, params?, timeout_ms? } } -> { state, matched }` atomic send-and-wait under the per-adapter mutex. Rust `ExtensionHandle::turn` counterpart. Requires both `input.write` and `matcher.wait` permissions.
  - JSON-RPC: `server.set_notifications` accepts optional `adapters?: string[]` and `sessions?: string[]` filters. UNION semantics; empty / omitted means "all". Adapter ids resolved at filter time so callers can pre-subscribe before `adapter.start` returns.
  - In-process event subscription: `Session::events() -> std::sync::mpsc::Receiver<SessionEvent>` (`Changed { sequence }`, `Exited(SessionExitStatus)`) and `ExtensionHandle::subscribe() -> mpsc::Receiver<ExtensionEvent>` (`StateChanged(snapshot)`). No async runtime dependency; dropped receivers pruned on the next event tick.
  - Cancellation primitive: `CancellationToken` (`Arc<AtomicBool>` wrapper) and `Session::wait_for_cancellable(matcher, timeout, &CancellationToken)`. New `Error::Cancelled` variant distinct from `Error::Timeout`. Idle waits cap their Condvar wait at 50 ms so cancels from other threads take effect promptly. `Error::UnsupportedOnPlatform` variant added alongside for platform-incompatible signals.
- `session.output` JSON-RPC notification carrying newly-appended transcript text (default-redacted) plus the sequence number. Fires from the same poll as `session.changed` whenever new output reaches the bounded transcript. Each connection keeps an independent cursor into the transcript's monotonic `chars_written` counter; if a slow subscriber falls behind the ring buffer's retention window, the next emitted notification carries the surviving tail and an explicit `dropped: true` flag. `server.capabilities` advertises `session.output` alongside `session.changed` / `session.exited`. New `Transcript::delta_since(cursor)` / `Session::transcript_delta_since(cursor)` / `Session::redacted_transcript_delta_since(cursor, policy)` powers the same delta access from Rust.
- `adapter.wait` responses now include a structured `matched` field describing which matcher branch fired (`{ kind, pattern?, capture?, text?, row?, col?, min_ms?, matched? }`). Regex branches surface the first capture group (or full match when no group is declared). Nested `Any` / `All` matchers recurse so callers can correlate the wake-up with the exact alternative they expressed. The Rust API gains `Matcher::describe_match[_with_context]` returning `Option<MatchOutcome>` and a new `outcome: Option<MatchOutcome>` field on `MatchResult`; `ExtensionHandle::wait` now returns `(ExtensionStateSnapshot, Option<MatchOutcome>)`.
- `claude-code` plugin now exposes `wait_cancel_settled_matcher` — a thin alias over `screen_stable(completed_turn_stable_ms)` that callers can pass to `adapter.wait` after `cancel`. The matcher fires once the screen has been stable for the same threshold the classifier uses internally for its `cancelling` hold-state, so the wait completes exactly when the classifier *would* release the hold if its `stable_ms` were forwarded (note: `adapter.state` doesn't forward `stable_ms`, so polling-based readers keep seeing `cancelling` until the next mutating intent — `adapter.wait` is the way to observe the post-cancel transition without re-implementing the threshold).
- `DefaultTarget` gained optional `rows` / `cols` fields so plugins can declare a classifier-stable headless terminal size. `adapter.start` falls back to the manifest preset when callers omit geometry, ahead of the host's last-resort `rows = 40, cols = 120`. The built-in `claude-code` plugin now ships a **`rows = 60, cols = 200`** preset wide enough to keep the status bar, prompt glyphs (`❯` / `>`), the "Total cost: …" usage screen, and the longest tool-use status lines off the wrap line. Caller-supplied `rows` / `cols` still win over the manifest preset.

A new `DefaultTarget::new(program)` constructor seeds the required field and leaves the rest at their defaults; external callers then assign the public optional fields directly (`target.args = …; target.rows = Some(60);`). Struct literals from outside the crate no longer compile against `DefaultTarget`. JSON/TOML representation is unchanged.
- New `adapter.resume` JSON-RPC method: convenience wrapper that takes the same parameters as `adapter.start` plus an optional `prior_adapter` id. When `prior_adapter` is supplied and still live, the host closes it before spawning the replacement so callers chaining sessions across PTY restarts (typically re-spawning with a `--resume <uuid>` style flag the TUI itself supports) don't have to make a separate `adapter.close`. Missing prior ids are silently ignored, keeping retries idempotent. Permission gate is `session.spawn` — identical to `adapter.start`.
- REPL DSL now mirrors the current adapter spawn/resume surface: `session.spawn(...)` accepts `args`, `cwd`, `env`, `pixel_width`, and `pixel_height` in addition to `program` / `rows` / `cols`, and new `session.resume(...)` calls `adapter.resume` with an optional `prior_adapter` (or `prior`) id while updating local focus/tab state.
- `claude-code` plugin exposes a new `steer` intent for mid-turn prompt injection. Same action shape as `send_prompt` (bracketed paste + Enter) but does NOT flip `last_intent` to `prompt_submitted`, so the classifier's `completed_turn` gate keeps waiting for the original turn to actually finish rather than mistaking a mid-turn stable screen for "turn complete". Verify against a recent Claude Code build before relying on it — the mid-turn input affordance is not version-stable.
- `ExtensionStateSnapshot` gained an opaque `metadata: Option<serde_json::Value>` channel for plugins to attach structured parsing of the screen alongside the state label. Omitted on the wire when empty. The struct is now marked `#[non_exhaustive]` and gains a public `ExtensionStateSnapshot::new(state, sequence)` constructor — external callers build via `new(...)` and then assign optional public fields (`snap.confidence = 0.95; snap.metadata = Some(...)`), since struct literals from outside the crate no longer compile against the non-exhaustive struct.
- `claude-code` classifier now parses the `/usage` panel when it reports `completed_turn` and attaches `{ usage: { cost_usd, api_duration_s, wall_duration_s, input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, lines_added, lines_removed } }`. Every field is best-effort and absent when the pattern didn't match, so a future TUI tweak that drops one of the lines just leaves that key out instead of breaking classification.
- `claude-code` classifier also parses the bottom status bar on every state and attaches `{ status: { model?, permission_mode? } }`. `model` comes from the `[Model Name]` brackets Claude renders in the status; `permission_mode` is one of `bypass` / `auto` / `plan` based on the `⏵⏵ … on` hint. Callers can read the running model and current permission mode without re-scraping the screen.
- `claude-code` classifier parses the permission dialog when state is `waiting_for_permission` and attaches `{ permission: { tool?, summary?, options } }`. Supports both layouts Claude Code ships today (numbered `❯ 1. Yes / 2. No` list and `[Enter] Approve / [Esc] Deny` bracketed style). Lossy vs `--permission-prompt-tool stdio`'s structured `control_request` — the TUI never renders the tool input JSON — but enough to apply simple policy gates from a calling consumer. The `summary` field is best-effort-redacted plugin-side (`token=`, `password=`, `api_key=`, `secret=`, `sk-…`, `AKIA…` patterns) because `adapter.state` / `send` / `wait` responses don't go through the host's `RedactionPolicy` like `adapter.snapshot` / `transcript` do; callers handling secrets must still treat metadata.permission.summary as best-effort, not as guaranteed-clean.
- Classifier fixture matrix (`tests/lua_classifier_tests.rs`) now honours an optional `metadata` field on `<fixture>.expected.json`; fixtures that need a structured assertion declare the expected JSON inline.
- `scripts/claude-stream.py` — single-command demo driver that spawns `ptywright serve --stdio`, starts the built-in `claude-code` adapter, auto-handles the workspace-trust dialog, submits a prompt, and streams live screen body + state transitions until the turn completes. Surfaces `metadata.status` / `metadata.permission` / `metadata.usage` inline. Wired into the devshell as the `claude-stream` command (`claude-stream "your prompt"`, `@file.md`, or `-` for stdin); auto-uses `target/release/ptywright` if built, otherwise falls back to a debug build. Defaults to `--model haiku` for fast smoke tests.
- New `welcome_persists_post_turn.txt` classifier fixture covering the Claude Code 2.1.x screen where the post-trust welcome panel stays rendered as visual residue after the user has submitted a prompt — locks in that the classifier now correctly reports `completed_turn` once the answer bullet is on screen rather than oscillating back to `starting`.
- `claude-code` classifier hardening for TUI-version-agnostic operation. The previous matchers for permission, plan, and active-work fell back to bare word matches that false-positived on Claude's answer prose (any answer that mentioned "permission", "approve", "thinking", "running tool" etc. would misclassify, blocking the classifier from ever reaching `completed_turn`). Tightened anchors:
  - **Permission**: requires structural anchors — focused numbered option (`❯ <digit>.`) following "Do you want to proceed?", or `[Enter]` + `[Esc]` together on one line. Earlier "verbatim phrase" approach kept tripping on prose that quoted those phrases; the structural shape is what's actually dialog-unique.
  - **Plan approval**: requires the structural pattern `plan` header line followed by a numbered list (`\n1[.)]`) — the actual dialog layout, not just the word "plan".
  - **Active work** (`thinking`): only the `esc to interrupt` hint and the spinner-glyph + verb + ellipsis structural pattern. Bare `thinking` / `running tool` / `reading file` removed.
  - **Ready text** (`ready` state): collapsed into `waiting_for_user_input`. The previous "what would you like" / "how can I help" matchers fired on answer prose; the prompt-glyph check covers the same intent without the false-positive.
- `claude-code` classifier: once `last_intent == "prompt_submitted"`, the welcome-panel detection no longer downgrades the state to `starting`. On Claude Code 2.1.x the welcome chrome can persist visually for the rest of the session, so without this gate the classifier oscillates between `thinking` (on ticks where the spinner is captured) and `starting` (between spinner frames), making turn-boundary polling unreliable. After submission the welcome chrome is treated as stale and the classifier falls through to the regular input-prompt / completed-turn branches.
- `claude-code` classifier: new poll-path `completed_turn` branch fires from `adapter.state` (no `stable_ms`) when the answer-bullet `⏺`, the `✻ <Verb> for <duration>` end-of-turn marker, AND an empty input-prompt line (`❯` / `>` alone on a line, optionally padded with U+00A0 NBSP) are all visible without an active-work spinner. The empty-prompt + marker pair guards against firing mid-stream or during preambles; the matcher-gated stable path (confidence 0.78) also requires the marker and still wins when `adapter.wait` supplies stability. Fixes two byte-level gotchas: `[>❯]` Lua character classes don't match multi-byte UTF-8 (`❯` is 3 bytes), and Claude Code 2.1.x pads the empty prompt with NBSP that Lua's `%s` does not include.
- `claude-code` `send_prompt` intent now emits **Enter → BracketedPaste → Enter** instead of just BracketedPaste → Enter. The leading Enter dismisses any first-keypress interceptor (welcome panel, compact-launch view) so the bracketed paste's CSI-200~ open marker isn't consumed as the dismiss event (which silently absorbed the rest of the paste on a fresh launch). On a clean empty input box Claude treats the leading Enter as a no-op submit.
- `adapter.start { plugin: "claude-code" }` with no geometry now spawns at **`rows = 60, cols = 200`** instead of **`rows = 40, cols = 120`**. Callers that need a different geometry pass `rows` / `cols` explicitly; nothing else changed about how the PTY is allocated.
- **Source-breaking Rust API change**: `DefaultTarget` gained `rows` / `cols` / `env` / `required_env` fields AND is now `#[non_exhaustive]`. Downstream code that constructed it with a positional struct literal (`DefaultTarget { program, args }`) must switch to `DefaultTarget::new(program)` and assign optional fields afterward (`target.args = …; target.rows = Some(60);`). The JSON / TOML representation is unchanged because all new fields are `#[serde(skip_serializing_if = "…is_empty")]` / `Option::is_none`.
- **Source-breaking Rust API change**: `ExtensionStateSnapshot` gained a `metadata` field AND is now `#[non_exhaustive]`. Downstream code that constructed it with a positional struct literal must switch to `ExtensionStateSnapshot::new(state, sequence)` and then assign optional fields afterward (`snap.confidence = …; snap.evidence = …`). The JSON-RPC wire shape is unchanged because `metadata` is `#[serde(skip_serializing_if = "Option::is_none")]`.

### Fixed

- `claude-code` classifier now recognises the spinner shape with a trailing parenthesized counter — e.g. `✻ Thinking… (12s · ↓ 339 tokens · thinking)`. The previous `has_thinking_spinner_line` required the line to literally end with `…`, so Sonnet 4.6's extended-thinking and Explore-subagent renders (which always append the counter section) fell through to the no-marker branch and the classifier reported "turn in flight; no completion marker" even though Claude was plainly working. Fix uses a structural check: leading spinner glyph + `…` + optional trailing `[ws]*([^)]*)[ws]*` counter section. The `is_progress_chrome_line` helper used by the marker-substance check tracks the same shape.
- `claude-code` classifier now scans the full screen (body + status bar) for the active-work indicator, not just the body. During Explore-subagent runs the main TUI body can be frozen for the entire duration but the status bar keeps repainting the spinner / token counter — and that's the only signal that work is still happening. The "esc to interrupt" / collapsible-tool-progress / spinner-shape patterns all reject every status-bar shape Claude Code 2.1.x renders, so widening the scan is structurally safe; the body-only restriction existed to avoid `permission` substring false-positives on `⏵⏵ bypass permissions on (shift+tab to cycle)`, which `has_active_work_indicator` never looked at to begin with. New fixture `thinking_in_status_bar.txt` pins the case.
- `claude-stream` ticker now surfaces a `+N.N KB/s` transcript-bytes indicator and scans the full screen (body + status_text) for the recent-activity line. Previously the alive ticker only read the body, so an Explore-subagent phase looked completely silent for tens of seconds even while Claude was streaming token-counter updates and spinner frames into the status bar. The bytes/sec sample refreshes once per second; the activity scan is union-of-regions so the spinner gets surfaced wherever Claude renders it.
- `claude-stream` no longer exits prematurely with empty output when a turn's content scrolls past the visible alt-screen body. The visible body is a fixed 60×200 cell snapshot; on a long answer or fast tool sequence, Claude's tool-call output and prose can roll out of view before the classifier fires `completed_turn`, at which point the body-only fallback (`_dump_answer_region`) finds nothing between its anchors and prints zero lines. The completion fallback now uses the full PTY transcript scrollback (`adapter.transcript`) as the primary source, anchored on the submitted prompt text and the trailing `✻ <Verb> for <duration>` marker, with the visible-body dump retained as a secondary fallback. The transcript captures every byte Claude wrote, so the user always sees the actual reply even when it rolled past the visible body.
- `claude-code` classifier: `has_turn_completion_marker` now also requires *substantive content* above the marker — at least one non-chrome, non-prompt-echo content line between the user's submitted-prompt echo and the marker line. Prevents the marker from firing when the body shows only the user's prompt echo plus chrome (spinner / horizontal rule / status bar) adjacent to a `✻ X for 0s` line — a shape that the parser captures briefly when Claude is initialising the turn before any real work has been rendered. If the prompt echo is not visible at all (scrolled off the top of the body because Claude wrote enough to push it past), the marker is trusted as-is. New fixture `premature_marker_no_content.txt` pins the no-content case to `thinking`; the existing `completed.txt` / `completed_real_status_bar.txt` / `completed_response_with_ellipsis_prose.txt` / `completed_response_quoting_dialog_anchors.txt` fixtures all continue to classify as `completed_turn`.
- `claude-stream` no longer goes silent during long `thinking` phases. The chrome filter was too aggressive — every line ending in `(ctrl+o to expand)` was suppressed, including completed tool-call summaries (`Read 5,103 lines (ctrl+o to expand)`, `Found 23 files (ctrl+o to expand)`, `Searched for X (ctrl+o to expand)`) which are exactly the lines a user wants to see. The filter is now restricted to the in-flight form (verb + ellipsis + ctrl+o), and the alive ticker surfaces the most recent tool-call activity inline so the gap between completions still shows progress instead of looking hung.
- `claude-stream` devshell command now refuses to run a stale `target/release/ptywright` or `target/debug/ptywright` binary when Rust or Lua plugin sources are newer, rebuilding debug first so classifier fixes are actually used during smoke runs. The devshell MOTD is also suppressed during `direnv export` reloads, and `claude-stream` gives spawned Claude sessions a quiet direnv config so shell/tool reload chatter does not pollute the stream.
- `claude-stream` no longer burns the full timeout waiting for `wait_turn_matcher` when Claude has not rendered prompt evidence yet; the initial settle wait is bounded, and the launcher keeps polling past the classifier's `ready` / "no screen evidence" fallback until real Claude evidence (input prompt, dialog, active work, or completion marker) appears. Shell / direnv / tool chatter rendered before Claude actually starts no longer races the paste.
- `claude-code` classifier no longer oscillates between `thinking` and `waiting_for_user_input` on mid-turn polling ticks. When `last_intent == "prompt_submitted"` and the TUI completion marker (`✻ <Verb> for <duration>`) is NOT on screen, the turn is by definition still in flight; the classifier now returns `thinking` regardless of whether the active-work spinner happens to be captured on this particular frame. The user's submitted prompt remains visible mid-turn (so `has_input_prompt` keeps returning true), and the previous logic flipped to `waiting_for_user_input` between spinner repaints — making `adapter.state` polling consumers (such as `claude-stream`) see spurious state churn that looked like flapping. The fix is timing-independent: the absence of the structural end-of-turn marker is the durable mid-turn signal.
- `claude-stream` pre-submit loop fails fast on `error` / `plugin_error` classifier states instead of polling them until the global deadline expires, and treats the welcome-screen `starting` state as a green light (the `send_prompt` intent's leading Enter already dismisses it). The previous loop spun on both cases until the hard timeout fired, masking the real failure as a generic deadline error.
- `claude-code` `send_prompt` intent now refuses an empty prompt — returns an empty action list and an explicit `last_intent = ""` clear sentinel (which `ExtensionHandle::apply_plan` and `apply_plan_with_required_intent` interpret as "drop any recorded intent") rather than recording a turn-in-flight intent against a no-op submission (the two Enters are no-ops on an empty input box, so Claude never renders the `✻ <Verb> for <duration>` completion marker that's the mid-turn release signal). Without this guard, classifying after an empty `send_prompt` would lock the state machine in `thinking` indefinitely. `claude-stream` already rejects empty prompts before this point, but the plugin-side guard makes the classifier robust to other consumers.
- `claude-stream` `direnv.toml` temp directory is now created inside the `try/finally` block that owns server cleanup, so a tempdir-creation failure can no longer leave the just-spawned `ptywright serve --stdio` subprocess running unattended.
- `claude-code` classifier: `has_permission_indicator` rewritten as a structural detector after the previous verbatim-phrase approach kept false-positiving on assistant prose that *quoted* the dialog anchors. A turn whose answer text mentioned `"Do you want to proceed?"` (e.g. summarising the plugin's own behaviour) would lock the classifier in `waiting_for_permission` forever. The detector now requires one of two dialog-unique structural shapes: the question line followed within ~6 rows by a focus glyph + numbered option (`❯ <digit>.`), or `[Enter]` AND `[Esc]` both rendered on the same line. The detector also reads the full screen instead of body-only so the numbered-options row (which can land in status-bar territory under tight geometries) is visible. New regression fixture `completed_response_quoting_dialog_anchors.txt` locks the prose-quoting case.
- `claude-code` classifier: both `completed_turn` branches (poll path and stable path) require the TUI's own end-of-turn marker — a `✻ <Verb> for <duration>` line such as `✻ Brewed for 1s` or `✻ Worked for 5s`. Without this gate, Claude's preamble pattern (a `⏺ I'll explore the project...` line followed by the input prompt for a single frame while the spinner was between repaints) was misread as turn completion and the script would terminate mid-stream. The marker glyph is shared with the spinner cycle, but completion lines end with ` for <num>` rather than the ellipsis spinner lines end with — that's the distinguishing tail. The completion gate also accepts prompt rows with Claude-rendered suggested follow-up text after the `❯` glyph (for example `❯ run the tests`) and no longer requires the `⏺` answer bullet to remain visible after long answers scroll, because the marker itself is the durable boundary. New `has_turn_completion_marker` helper plus regression fixture `preamble_before_tool_use.txt` locks the preamble case to `thinking`.

Callers must use the generic `adapter.*` surface instead. `adapter.start` accepts `{"plugin": "claude-code"}` and reads the manifest's `default_target` so the program does not need to be passed explicitly; `adapter.send` accepts `{"intent": "send_prompt"|"approve"|"deny"|"cancel"|...}` for every mutation that `claude.*` previously exposed.
- **Breaking:** the typed Rust adapter shim (`ClaudeCodeAdapter`, `ClaudeCodeConfig`, `ClaudeCodeState`, `ClaudeCodeStateSnapshot`) and the entire `src/adapters/` module. Rust callers should drive plugins through `ExtensionHandle` + `LuaExtension::built_in(<name>)` and read state strings off `ExtensionStateSnapshot` directly.
- `claude_code_manifest` is no longer part of the public library surface; use `builtin_manifests()` to enumerate registered plugins.

### Security

- Per-method permission gating at the JSON-RPC dispatcher. Every `adapter.*` method (except read-only registry queries `adapter.list` / `adapter.live`) consults the bound plugin manifest's declared `permissions` before invoking the handler. Method → permission mapping: `adapter.start` → `session.spawn`, `adapter.send` → `input.write`, `adapter.wait` → `matcher.wait`, `adapter.snapshot` / `adapter.state` / `adapter.inspect` → `screen.read`, `adapter.transcript` → `transcript.read`, `adapter.close` → `session.kill`. Denied calls return new JSON-RPC error code `-32004 PermissionDenied` with structured `data: { method, required_permission }`. The built-in `claude-code` manifest declares all seven permission variants so existing callers see no behaviour change.
- New `Error::PermissionDenied { method, required }` variant in the public library surface.
- `plugin.load` / `plugin.unload` JSON-RPC methods require the server to have been started with `--allow-plugin-load`; without it both return `-32004 PermissionDenied` with `data.reason = "server_did_not_grant_plugin_load"`. The CLI `--plugin <manifest.toml>` flag works regardless because operators load plugins at startup, which is explicitly trusted.

### Fixed

- `cargo install ptywright` no longer installs the test-only `ptywright-echo-tui` fixture binary alongside the real CLI. The fixture is now gated behind an internal `_test-fixtures` Cargo feature via `required-features`, so it is only built when CI test runs (and the devshell `run-tests` / `ci-local` commands) enable it explicitly.
